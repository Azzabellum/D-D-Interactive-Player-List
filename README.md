# D&D IPL — локальное приложение

Версия 0.2: интерфейс, аккаунты, кампании, серверные права и SQLite. React + TypeScript, Fastify, встроенный SQLite Node.js. Спецификация: [TECHNICAL_SPEC.md](TECHNICAL_SPEC.md).

## Запуск

Требуется Node.js 24+ и pnpm. Из папки проекта:

```sh
pnpm install
pnpm build
pnpm start
```

Открыть **http://127.0.0.1:3001**. Сервер работает, пока запущена команда. Остановка — Ctrl+C. Для разработки: `pnpm dev` запускает сервер и Vite, адрес интерфейса **http://127.0.0.1:5173**. Проверки: `pnpm test` и `pnpm build`.

## Первый вход

1. При первом запуске создать собственные логин и пароль мастера на ноутбуке. Стандартного пароля и готовых аккаунтов в рабочей базе нет.
2. Создать кампанию и открыть её.
3. В «Настройки → Участники кампании» создать одноразовый код. Он действует 24 часа и выдаёт только роль игрока.
4. Игрок выбирает «У меня есть приглашение», вводит код и создаёт свой аккаунт. Для существующего аккаунта есть поле приглашения в списке кампаний.
5. Игрок создаёт персонажа и отправляет анкету. Мастер утверждает её или возвращает с комментарием.

Сейчас сервер слушает только локальный адрес: удалённые игроки смогут подключиться после отдельной настройки Tailscale и HTTPS. На текущем этапе можно проверять двух пользователей в разных браузерах или в обычном и приватном окнах. Сессия общая для вкладок одного браузерного профиля.

## Темы и текст

- Кнопка солнца/луны в шапке переключает светлую и тёмную темы. Переключатель роли убран: роль определяет сервер для выбранной кампании.
- «Настройки → Оформление и читаемость»: масштаб текста 100%, 115% и 130%. Мелкие информационные подписи увеличены; браузерное масштабирование также работает.
- Сила — красный, ловкость — зелёный, телосложение — оранжевый, интеллект — синий, мудрость — бирюзовый, харизма — фиолетовый. Цвета применяются к характеристикам, тегам предметов и примерам навыков; названия всегда видимы.
- Тема и масштаб сохраняются только на текущем устройстве, независимо от кампании.

## Что работает

Аккаунты с хешированными паролями, вход/выход и отзыв сессии, кампании, приглашения, отключение участника, черновики и утверждение, здоровье, выдача и изъятие предметов, раскрытие скрытых свойств, заметки, история и отмена последнего совместимого изменения. Изменения других клиентов приходят через WebSocket; дополнительно снимок обновляется каждые 5 секунд, в том числе после потери WebSocket.

Права проверяются в API. Игрок получает только собственных персонажей. Скрытые свойства и заметки мастера отсутствуют в ответе игроку. Личные заметки игрока отсутствуют в ответе мастеру; владелец ноутбука всё равно имеет доступ к файлам базы.

Анкеты и заметки сохраняются явной кнопкой. При конфликте версий текст заметки остаётся в редакторе и его можно скопировать перед загрузкой серверной версии. При уходе из заметок или анкеты персонажа, смене вида заметки и выходе из аккаунта приложение предупреждает о несохранённых изменениях. Закрытие или обновление вкладки вызывает стандартное предупреждение браузера, если браузер его поддерживает. Это не автосохранение: после подтверждённого ухода текст теряется. Защита также действует в диалогах предметов, способностей, инвентаря, параметров, здоровья и описания кампании, а также при уходе со страницы с введённым текстом импорта. Закрытие изменённого диалога кнопкой, Escape или фоном требует подтверждения там, где такой способ закрытия доступен. Автосохранение — дальнейшая доработка.

## Данные и ограничения этапа

Рабочие данные: `data/database.sqlite` и сопутствующие SQLite-файлы WAL/SHM. Папка исключена из Git. Перезапуск сохраняет аккаунты и кампании. Старые данные прототипа в localStorage не удалены, но не импортируются автоматически. Сервер создаёт ежедневные согласованные копии в `data/backups` и хранит последние 10 автоматических снимков. Ручная копия: `pnpm backup create`; список: `pnpm backup list`. Проверка и локальное восстановление при остановленном сервере описаны в [инструкции резервирования](docs/BACKUPS.md).

Начальные библиотечные предметы пока демонстрационные; в анкете доступен один проверенный стартовый шаблон и ручной режим. Редакторы предметов, заклинаний и особенностей позволяют мастеру создавать собственные карточки. Проверенный набор SRD, портреты, владения, происхождения, повышение уровня и полный движок D&D относятся к дальнейшим этапам. Здоровье и защита нового персонажа — заготовки, а не полный расчёт класса. Теги показывают связь с характеристикой и не применяют бонус автоматически.

Переменные окружения: `IPL_DB` — путь к базе; `PORT` — порт (по умолчанию 3001); `IPL_HOST` — адрес привязки (127.0.0.1); `IPL_ORIGINS` — точные разрешённые адреса интерфейса через запятую. Удалённая публикация не выполнялась. Не используйте Vite как сервер для игровой группы.

## Изолированный стенд проверки

После сборки: `node tests/preview.mjs`, адрес http://127.0.0.1:3002. Данные существуют только в памяти, не затрагивают рабочую базу и исчезают при остановке. Тестовые аккаунты: `preview-master` и `preview-player`, пароль для обоих — `Preview-only-2026!`. Они существуют только на отдельном стенде, который слушает локальный адрес.

## Редактор предметов

В кампании откройте «Библиотека» → «Создать предмет». Мастер задаёт название, произвольный тип, описание, скрытое свойство и теги характеристик. Кнопка «Редактировать» меняет шаблон, включая демонстрационные карточки. Новые типы автоматически появляются в фильтре.

Шаблоны сохраняются в SQLite отдельно для каждой кампании и доступны только мастеру. При выдаче создаётся независимый экземпляр: дальнейшее изменение шаблона не меняет инвентарь персонажа. Скрытое свойство нового шаблона выдаётся нераскрытым. Выдача и изменения инвентаря используют существующую историю и отмену; отдельная история редактирования шаблонов пока не добавлена.

Редактор сохраняет по кнопке; при конфликте версий он не перезаписывает чужую правку и оставляет текст в открытой форме. Закрытие формы без сохранения отменяет ввод. Учёт зарядов описан ниже; числовые эффекты экипировки описаны ниже. Вес описан ниже. Урон, стоимость и сложные эффекты остаются в плане.

## Заклинания и особенности

«Библиотека → Заклинания и особенности» доступна мастеру. Здесь можно создать, изменить или скопировать карточку, найти её по названию, отфильтровать по виду и выдать выбранному персонажу. Начальная библиотека пуста: встроенный проверенный набор SRD появится на этапе правил.

У заклинаний есть круг (0 — заговор), время накладывания, дистанция, длительность, компоненты, концентрация и ритуал. У обеих разновидностей есть описание, источник и цветовые теги характеристик. Все поля выданной карточки видны владельцу персонажа; секреты в этот редактор не вводятся.

Выданные карточки находятся в листе → «Способности», отдельно от инвентаря. Мастер может убрать карточку; выдача и удаление записываются в историю и поддерживают отмену последнего совместимого изменения. Изменение шаблона не меняет выданные копии. Игроку доступны только выданные его персонажам карточки, без редактора и библиотеки мастера.

Это текстовые правила: приложение ещё не рассчитывает эффекты, подготовку заклинаний и расход ячеек. Сохранение формы явное; закрытие без сохранения отменяет ввод. Архивация и перенос шаблонов доступны в разделе «Перенос и архив»; отдельная история шаблонов остаётся в плане.

## Состояние инвентаря

При выдаче обычного предмета мастер указывает количество (1–9999). В инвентаре кнопка «Изменить состояние» открывает количество, экипировку, настройку и текущие заряды. Настройка доступна только для требующего её предмета; заряды ограничены максимумом. Максимум зарядов и необходимость настройки задаются в шаблоне библиотеки. Новый экземпляр получает полный запас зарядов, без экипировки и настройки.

Предметы с зарядами или настройкой учитываются отдельно, по одному экземпляру. Обычные предметы можно хранить стопками; «Отделить одну единицу» разделяет исходную стопку без изменения общего количества. Эта кнопка сразу сохраняет разделение исходной стопки, не применяя несохранённые поля формы. Экипировка доступна для одной единицы. Для удаления всей позиции используется «Забрать».

Игрок видит состояние, но не изменяет его. Изменения, разделение и выдача записываются в историю с отменой. Старые экземпляры без новых полей отображаются как одна единица в сумке. Числовые эффекты задаются в редакторе предмета. Ограничения настройки по правилам и восстановление зарядов пока не рассчитываются; решения принимает мастер. Изменение шаблона не меняет параметры уже выданных экземпляров.

## Расчёты и параметры персонажа

Мастер открывает «Обзор → Изменить параметры». Здесь задаются уровень (1–20), шесть характеристик, владения навыками и спасбросками, экспертиза, хиты и КД. Сервер рассчитывает бонус мастерства, 18 навыков, спасброски, инициативу и пассивную внимательность; рядом с итогами показаны слагаемые. Изменения записываются в историю и отменяются вместе с исходными значениями.

Лист до проверки мастером явно помечен. Класс/происхождение пока не назначают владения автоматически. Хиты и КД задаются вручную; изменение максимума не меняет текущие хиты без явного ввода. Повышение уровня и классовые эффекты ещё не автоматизированы. Предметы применяют только явно настроенные числовые эффекты. Область расчётов и атрибуция: [docs/RULES.md](docs/RULES.md). Оставшиеся этапы: [docs/ROADMAP.md](docs/ROADMAP.md).

## Первый стартовый шаблон SRD

В «Создать персонажа» по умолчанию выбран проверенный шаблон «Дварф · Воин · Солдат», уровень 1. Можно распределить стандартный массив, бонусы происхождения, два навыка, два языка, игровой набор и три вида оружия для мастерства. Боевой стиль — Оборона, снаряжение выбрано деньгами (205 зм). Сервер создаёт стартовые хиты, КД без доспехов, владения и карточки особенностей. Их применение во время игры учитывает мастер.

На первом шаге до сохранения можно выбрать ручную анкету для других сочетаний; их параметры проверяет мастер. Старые персонажи не изменяются. Состав, источники и ограничения: [docs/STARTER_PACK.md](docs/STARTER_PACK.md).

## Перенос и архив библиотек

«Библиотека → Перенос и архив» доступна только мастеру. Экспортирует активные шаблоны предметов (включая начальные карточки), заклинаний и особенностей в JSON. Файл содержит скрытые свойства, но не содержит персонажей, аккаунтов, приглашений, заметок или истории. Это перенос контента, а не резервная копия кампании.

Для импорта выберите JSON или вставьте его текст, нажмите «Проверить файл», проверьте список и нажмите «Импортировать копии». Сервер проверяет весь набор до сохранения; ошибка не оставляет частичного импорта. Все карточки получают новые ID, существующие не перезаписываются. Повторный отдельный импорт намеренно создаёт ещё один набор. Ограничения: версия формата 1, до 100 предметов и 100 способностей, файл до 2 МБ. Если экспорт слишком большой, временно архивируйте часть карточек и перенесите библиотеку несколькими файлами.

Кнопка «В архив» на карточке убирает её из активной библиотеки и выбора при выдаче. «Восстановить» возвращает её. Уже выданные экземпляры остаются у персонажей. Архив хранится вместе с шаблонами в SQLite; необратимого удаления нет. Изменять архивную карточку можно после восстановления. Операции архива и импорта проверяют версию кампании; отдельный журнал изменений шаблонов пока не добавлен.

При обрыве связи повторно подключается WebSocket (пауза от 1 до 30 секунд), а опрос сервера каждые 5 секунд остаётся запасным способом обновления. Возврат в окно и восстановление сети запускают проверку; при ошибке доступна кнопка «Проверить связь». Несохранённая заметка остаётся в поле, обновление не затирает её. При истечении сессии или отзыве доступа приложение возвращает к выбору/входу; сохранность ввода в этом случае не обещается.

История поддерживает поиск по названию действия, описанию и имени персонажа, выбор персонажа и статус отмены. Фильтры применяются к последним 200 событиям, полученным от сервера; более старые записи в базе не удаляются. Доступность отмены проверяется по всей загруженной истории, независимо от фильтра.

## Игровые ресурсы

В листе → «Способности» мастер может настроить ячейки заклинаний и расходуемые способности, отмечать расход и возвращать единицы. Короткий и долгий отдых восстанавливают заданные мастером количества с предварительным просмотром. Игрок видит остатки; изменения доступны только мастеру и поддерживают отмену через историю. Лимиты не рассчитываются по классу автоматически; здоровье и кости хитов отдых пока не меняет. [Подробности и ограничения](docs/RESOURCES.md).

## Бонусы и штрафы

В листе → «Способности» → «Бонусы и штрафы» мастер задаёт до 50 поправок с источником: к КД, инициативе, конкретному навыку или спасброску. Включённые значения складываются с базой на сервере, источники показаны в листе; поправку можно выключить без удаления. Изменения сохраняются в истории с отменой, игрок только читает. Все названия источников видны игроку.

КД в настройках — базовое значение, итоговый КД отображается в листе и группе. Поправка к внимательности также меняет пассивную внимательность. Совместимость, длительность и ситуативность проверяет мастер; отдых и текст карточек не включают и не снимают ручные поправки автоматически. Эффекты, заданные в редакторе предмета, зависят от экипировки и настройки. Это числовое сложение, а не автоматическая реализация эффектов D&D: преимущества, помехи, замена формул и ограничения сочетаний не рассчитываются. Не вводите один бонус одновременно в базовый КД и отдельную поправку.

## Эффекты экипировки

В редакторе предмета раздел «Числовые эффекты экипировки» задаёт бонус или штраф к КД, инициативе, конкретному навыку или спасброску. До 26 эффектов на предмет, по одному на каждую цель, целые ненулевые значения от −30 до +30. Числовые эффекты публичны и не зависят от раскрытия скрытого свойства.

Выданный предмет применяет эффекты, когда экипирован; если требует настройки — также должен быть настроен. При снятии, отмене настройки или изъятии бонус исчезает. Источник в расчётах — название предмета. Ручные поправки и эффекты предметов суммируются; совместимость и ограничения одинаковых предметов проверяет мастер. Не дублируйте один бонус в базовом значении, ручной поправке и предмете.

Это добавление чисел, а не формула доспеха, урон, преимущество или эффект за расход зарядов. Количество и заряды не умножают бонус. Шаблон влияет только на будущую выдачу: уже выданные экземпляры независимы. Эффекты входят в перенос библиотеки, историю персонажа и резервные копии. Старые предметы не получают эффектов автоматически.

## Состояния и концентрация

В листе → «Обзор» мастер может отметить до 20 состояний с произвольным названием, источником, длительностью и пояснением. Концентрация — одна отдельная запись; при вводе предлагаются названия выданных заклинаний с отметкой концентрации, также можно ввести своё. Все поля видны игроку. В списке группы показываются число состояний и название концентрации.

Состояния и концентрация сохраняются явной кнопкой, поддерживают защиту несохранённого ввода, проверку версии и отмену через историю. Чтобы снять состояние, удалите его из списка и сохраните; чтобы закончить концентрацию, снимите отметку и сохраните. Старые персонажи не получают состояний автоматически.

Это ручной учёт: нет таймера, автоматических спасбросков, преимуществ/помех, штрафов или снятия после урона/отдыха. Отметка концентрации не расходует ячейку. Числовые поправки задаются отдельно; снятие состояния не отключает их автоматически. Стандартный справочник состояний и их механики пока не реализованы.

## Вес инвентаря

Вес одной единицы задаётся мастером в килограммах с точностью до грамма: в редакторе шаблона или в «Изменить состояние» выданного предмета. Пустое поле означает неизвестный вес, 0 — явно невесомый предмет. Для удаления значения можно использовать кнопку «Очистить вес». Разрешён диапазон 0–1 000 000 кг на единицу. Сервер хранит целые граммы и суммирует вес с учётом количества, включая экипированные предметы. При разделении стопки общий вес сохраняется.

В инвентаре видны вес каждой позиции и итог. Если есть предметы без указанного веса, показана неполная сумма и количество неизвестных позиций/единиц. Вес старых предметов, золота и стартового снаряжения не угадывается автоматически. Лимиты переноски, штрафы, вложенные контейнеры и особые свойства сумок пока не рассчитываются. Изменение шаблона не меняет выданные экземпляры. Вес входит в историю персонажа, экспорт библиотеки и резервные копии; игрок только читает.


## Карточки создания персонажа — основная книга 2024

Новая анкета проходит шесть шагов: вид → класс → происхождение → личность → характеристики → проверка. В каталоге 10 видов, 12 классов и 16 происхождений основной книги 2024, с поиском и открываемым описанием. Это краткие авторские обзоры, а не полный текст правил. Сохранение требует всех трёх выборов и имени.

Мастер открывает «Библиотека → Создание персонажа» и может создавать, копировать, изменять и архивировать карточки каждого типа. Изменения действуют только в текущей кампании. Архивные карточки недоступны для нового выбора, но сохраняются в старых анкетах. Для персонажа сохраняются снимки выбранных описаний: изменение каталога и повторное сохранение того же выбора их не переписывают. Они видны в биографии. Если игрок выберет другую карточку, сохранится её актуальный текст.

Редактор защищает несохранённый ввод и проверяет версию кампании. Отдельная история изменений каталога и его перенос JSON пока не реализованы. Карточки входят в резервную копию базы. Старые анкеты с текстовыми полями продолжают работать; при переходе на карточки нужно выбрать все три категории.

Тексты карточек не меняют числовые параметры. Проверенный автоматический старт по-прежнему доступен для Дварфа / Воина / Солдата через отдельную отметку на шаге личности. Остальные сочетания проверяет и настраивает мастер. План постепенной автоматизации приведён в docs/RULES_IMPLEMENTATION.md.


## Прибавки происхождения и языки

На шаге «Характеристики» новой анкеты можно включить «Рассчитать прибавки и сохранить языки». Доступно для происхождений с тремя настроенными характеристиками: встроенные Послушник, Преступник, Мудрец, Солдат, Скиталец. Для остальных мастер задаёт три характеристики в редакторе карточки (или оставляет ручную проверку).

Выбор +2/+1 или +1/+1/+1 проверяется сервером. База хранится отдельно от итога, повторное сохранение не удваивает прибавки. Общий язык известен изначально, два дополнительных выбираются из обычных и не должны совпадать. Выборы видны в биографии. Дополнительные языки от классов/черт и их изменение после утверждения пока учитываются через способности и заметки мастера.

Способ расчёта закрепляется при первом сохранении: старые ручные анкеты автоматически не преобразуются. Полный стартовый шаблон Дварф/Воин/Солдат использует свой прежний расчёт и не складывается с новым блоком. Владения, черты, хиты и снаряжение остальных сочетаний ещё проверяет мастер. При смене происхождения выбранные прибавки сбрасываются; нужно распределить их заново. Снимок правил уже выбранного происхождения не меняется вслед за каталогом.


## Владения происхождения — 19 сентября

Для новых анкет с включённым расчётом первого уровня навыки происхождения автоматически учитываются отдельным источником. Готовые данные: Послушник (Проницательность, Религия; каллиграфия), Преступник (Ловкость рук, Скрытность; воровские инструменты), Мудрец (Магия, История; каллиграфия), Солдат (Атлетика, Запугивание; выбор игрового набора), Скиталец (Проницательность, Скрытность; воровские инструменты).

На шаге характеристик показаны навыки и фиксированный инструмент либо обязательный выбор одного инструмента. Владение не выдаёт предмет. В редакторе происхождения мастер может указать два навыка и до 20 вариантов инструмента (один на строку). Без настроек поля остаются ручными. Начальные черты, оборудование и классовые владения пока не выдаются этим блоком.

Навыки не складываются с ручным владением: применяется наибольшая ступень, экспертиза сохраняется. Мастер может отключить источник целиком в параметрах персонажа; операция попадает в историю и поддерживает отмену. Инструменты показаны в биографии как запись о владении, броски инструментов не автоматизированы. У старых анкет со снимком карточки без новых полей владения не появляются автоматически. При смене происхождения при создании старый выбор инструмента сбрасывается.

Источники: https://www.dndbeyond.com/sources/dnd/br-2024/character-origins и https://www.dndbeyond.com/posts/1785-the-backgrounds-and-origin-feats-in-the-2024 .


## Навыки и спасброски всех 12 классов

На шаге характеристик при включённом расчёте первого уровня доступна отметка «Применить владения класса». Выберите нужное число навыков: Бард и Следопыт — 3, Плут — 4, остальные — 2. Выбор ограничен списком класса; уже полученные от происхождения навыки отмечены и не занимают новый выбор. Спасброски класса добавляются автоматически. Классовый источник не удваивает бонус мастерства и не заменяет ручную экспертизу.

Мастер может настраивать число и список навыков, а также два спасброска в редакторе карточки класса. В параметрах листа источник класса можно отключить целиком, с записью в историю и отменой. Снимки старых карточек не обновляются автоматически: старые анкеты могут продолжать ручную настройку. Выбор навыков сбрасывается при смене класса или происхождения. Эти правила применяются к первому классу на первом уровне, не к мультиклассу.

Это автоматизация навыков и спасбросков. Экспертиза Плута, инструменты, оружие, доспехи, классовые особенности и повышение уровня ещё требуют отдельных блоков. Проверенные таблицы: https://www.dndbeyond.com/sources/dnd/br-2024/character-classes .


## Экспертиза первого уровня

Новая карточка Плута требует выбрать два разных освоенных навыка при включённых классовых владениях. Можно выбрать навыки класса или происхождения. Экспертиза удваивает бонус мастерства, но не складывается с ручной экспертизой. Изменение класса/происхождения сбрасывает выбор, удаление базового владения требует исправить экспертизу перед сохранением. Мастер может задать число навыков с экспертизой (0–2) в карточке своего класса.

Источник экспертизы отключается вместе с классовыми владениями. При отключении происхождения экспертиза его навыка не действует, если больше нет владения от класса или ручной настройки. Старые снимки классов без нового поля продолжают работать; уже существующие листы автоматически не получают новую способность. Повышение уровня Плута и экспертиза Барда на последующих уровнях остаются отдельной задачей.

Источник: https://www.dndbeyond.com/sources/dnd/br-2024/character-classes (Rogue, Level 1: Expertise).


### Классовое снаряжение — реализовано 19.09.2026

В общем создании первого уровня при включённых владениях класса сохраняются базовые владения оружием, доспехами и инструментами всех 12 классов. Бард выбирает три музыкальных инструмента, монах — один музыкальный или ремесленный; друид получает набор травника, плут — воровские инструменты. Повтор инструмента от происхождения отображается один раз в сводке активных источников и не даёт экспертизу.

Мастер настраивает фиксированные владения и варианты инструментов в редакторе карточки класса. Сервер проверяет количество, уникальность и допустимость выбора; клиент не задаёт итоговые владения. Сохранённые снимки карточек неизменны, старые анкеты без этих данных продолжают работать. Изменения источников отражаются в существующей истории/отмене. Новые поля хранятся в JSON текущей схемы БД.

Это учёт владений: он не выдаёт снаряжение и не рассчитывает атаки, КД, ограничения ношения доспехов или оружейные приёмы. Дополнительные владения от Divine Order / Primal Order, мультикласс и особенности следующих уровней остаются следующими блоками. Следующий шаг: общие хиты первого уровня и стартовое снаряжение, затем особенности классов и видов.

Источники: [Basic Rules 2024 — классы](https://www.dndbeyond.com/sources/dnd/br-2024/character-classes), [инструменты](https://www.dndbeyond.com/sources/dnd/br-2024/equipment).


### Хиты и стартовое снаряжение — 19.09.2026

В общей анкете firstLevel появился независимый выбор расчёта хитов: кость класса + модификатор итогового Телосложения + настроенные firstLevelHpBonus выбранных карточек. Для дварфа задан +1. Мастер может настроить кость класса и прибавки в редакторе. Способ расчёта фиксируется при первом сохранении; расчёт работает только при сохранении черновика, не лечит утверждённых персонажей и не заменяет ручные правки мастера. Прочие бонусы черт (включая Tough) пока не назначаются автоматически.

Все 12 классов имеют выбор денежной альтернативы или стартового набора; у воина два набора. Бард выбирает один музыкальный инструмент для выдачи, монах — инструмент своего выбранного владения. Происхождение отдельно предлагает 50 зм вместо набора; готовые наборы происхождений остаются следующим шагом. Общая анкета по-прежнему требует настроенных прибавок происхождения (преднастроены пять происхождений; остальные настраивает мастер).

Выдача серверная, со стабильными ID first-level:<character-id>:*. Повторное сохранение заменяет только выданные этим механизмом позиции, сохраняя прочие предметы; отмена выбора убирает стартовую выдачу в черновике. В биографии остаётся начальный расчёт и сумма, текущие деньги находятся в инвентаре. Снимки карточек сохраняют правила старых анкет. Старые персонажи без новых выборов не меняются.

Наборы путешественника/учёного и другие комплекты хранятся одной позицией. Состав готовых классовых наборов пока не редактируется в интерфейсе; после выдачи мастер меняет инвентарь. Автоматической экипировки, веса, урона и КД у этих позиций нет. Следующие блоки: наборы происхождений, детализация предметов, боевые расчёты, особенности и черты.

Проверка: 46 тестов; все классы и наборы, отрицательный модификатор Телосложения, дубли, замена выдачи, фиксация способа расчёта, защита от подмены и права после отправки.

Источники: [классы](https://www.dndbeyond.com/sources/dnd/br-2024/character-classes), [начальные хиты](https://www.dndbeyond.com/sources/dnd/br-2024/creating-a-character), [происхождения и дварф](https://www.dndbeyond.com/sources/dnd/br-2024/character-origins).


### Наборы происхождений — 20.09.2026

Добавлены готовые наборы четырёх происхождений из открытых Basic Rules 2024: послушник, преступник, мудрец, солдат. В анкете независимо выбираются набор/золото/выдача мастером для класса и происхождения. Солдат получает игровой набор из выбранного владения происхождения. У остальных происхождений пока доступно золото или выдача мастером.

Новый firstLevel.backgroundEquipment заменяет переключатель backgroundGold в интерфейсе; старое поле читается для совместимости. Сервер отвергает конфликт «набор + старое золото», неизвестные наборы и неподходящие инструменты. Предметы происхождения имеют отдельные стабильные ID внутри first-level:<id>:background:; замена набора на золото удаляет предыдущую стартовую выдачу, сохраняя сторонние предметы. Сохранённая версия карточки остаётся источником правил. После отправки игрок не меняет выдачу.

Свойства оружия, вес и КД стартовых предметов пока не автоматизированы. Следующий блок — структурированные свойства предметов и разворачивание комплектов. Проверено: 48 тестов, включая состав четырёх наборов, повторное сохранение, смену варианта, старые анкеты, снимки каталога и запрет правок после отправки.

Источник: [Basic Rules 2024: Character Origins](https://www.dndbeyond.com/sources/dnd/br-2024/character-origins).


### Снаряжение и бой — 20.09.2026

Реализован единый боевой профиль предмета: оружие (категория, тип атаки, кости/тип урона, свойства, универсальный урон, дальность, мастерство, магические прибавки) или доспех/щит (категория, база КД, магическая прибавка, Сила, помеха Скрытности). Справочник содержит 35 профилей оружия и 13 доспехов/щита. Профиль и вес можно перенести в шаблон или выданный экземпляр; поля редактирует мастер. Вес переведён из фунтов в граммы с округлением. Конное копьё и огнестрельное оружие пока не преднастроены.

Новые стартовые наборы содержат профили соответствующего оружия/доспехов в снимках карточек. Старые снимки и ранее выданные предметы не переписываются; мастер может назначить им профиль в редакторе инвентаря. Профили не выводятся из названия предмета на сервере.

В листе появились атаки экипированным оружием: модификатор Силы/Ловкости, бонус мастерства один раз при владении, отдельные магические прибавки. Фехтовальное использует больший модификатор; метательное оружие ближнего боя сохраняет Силу/фехтовальное. Владение берётся из активных сохранённых классовых владений (включая исключения монаха/плута) либо из явного решения мастера у предмета. У старого стартового шаблона воина учитываются его владения.

Новый режим acMode=equipment включается только мастером в параметрах персонажа. База: без доспеха 10+Ловкость; лёгкий +Ловкость, средний +Ловкость максимум +2 (отрицательная сохраняется), тяжёлый без Ловкости. Щит учитывается только при владении. Несколько доспехов/щитов вызывают предупреждение и возврат к ручной базе вместо сложения. Существующие числовые эффекты/поправки прибавляются один раз после базы; мастер не должен дублировать записанный бонус профиля в эффектах. По умолчанию старые листы остаются на ручном КД.

Физические свойства предмета действуют и без настройки, магические прибавки профиля — после требуемой настройки. Предупреждения показывают ограничения тяжёлого оружия, две руки при щите, Силу доспеха, отсутствие владения доспехом, Скрытность и боеприпасы. Ограничения не заменяют решения мастера и не блокируют броски/заклинания автоматически.

Это обычные атаки оружием: боевые стили, монашеская замена характеристик/костей, критические попадания, дополнительная атака лёгким оружием, применение мастерства, особая защита монаха/варвара и магии, дистанция до цели, действия, расход боеприпасов и броски пока ручные. Содержимое походных комплектов не разворачивается.

Валидация строгая на сервере; профили доступны существующим библиотеке/выдаче/импорту и истории с отменой, новых таблиц БД не нужно. Проверка: 52 теста, включая матрицу КД/атак, владения, настройку, конфликты, права игрока и отмену.

Источник: [Basic Rules 2024 — Equipment](https://www.dndbeyond.com/sources/dnd/br-2024/equipment). Используется существующее указание авторства SRD 5.2.1 / CC BY 4.0 в листе.
