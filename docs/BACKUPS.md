# Резервные копии

Все команды выполняются в папке проекта на ноутбуке мастера. Это локальное обслуживание установки; веб-доступа к резервным копиям пока нет.

## Автоматически

Сервер проверяет необходимость копии при запуске и каждый час. Если последнему автоматическому снимку не меньше суток, создаётся новый. Хранятся последние 10 успешных автоматических копий; ручные и защитные копии не удаляются автоматически. При выключенном сервере расписание не работает. Ошибки выводятся в терминал сервера.

Каталог по умолчанию: `data/backups`. При `IPL_DB` используется каталог `backups` рядом с указанной базой. Снимок создаётся командой SQLite `VACUUM INTO`, включая подтверждённые записи WAL; копировать работающий `database.sqlite` обычными файловыми средствами не нужно. Незавершённый файл не попадает в список готовых копий.

## Ручная копия и проверка

```powershell
pnpm backup create
pnpm backup list
pnpm backup check "C:\полный\путь\к\копии.sqlite"
```

Ручную копию можно создавать при работающем сервере. Готовый `.sqlite` можно скопировать на другой носитель. Файл содержит всю установку: аккаунты с хешами паролей, кампании, персонажей, библиотеки, историю, личные и секретные заметки. Храните его как личные данные. Копии на том же диске не защищают от поломки диска.

## Восстановление

1. Остановите сервер (`Ctrl+C` в терминале запуска).
2. Выполните `pnpm backup check "путь к копии.sqlite"`.
3. Выполните `pnpm backup restore "путь к копии.sqlite"`.
4. Запустите приложение обычным способом. Всем участникам потребуется войти заново; неиспользованные приглашения отозваны.

Команда проверяет целостность SQLite, внешние ключи, обязательные таблицы/поля, JSON игровых записей и версию схемы. Затем готовит отдельный файл, создаёт защитный снимок текущей базы `before-restore-*`, закрывает соединения и заменяет рабочую базу. При работающем сервере восстановление запрещает файловая блокировка. После аварийного завершения процесса блокировка снимается автоматически только если записанный процесс больше не существует.

Восстановление поддерживает схемы 3 и 4. При запуске база схемы 3 автоматически обновляется до 4 с защитным снимком; схема 4 включает каталог создания персонажа. Снимки `before-update-*` создаются перед обновлением старой схемы, но для отката на старую схему нужна соответствующая версия приложения. База более новой версии не открывается текущим сервером. Если текущая база повреждена настолько, что защитный снимок не проходит проверку, обычное восстановление останавливается: сохраните повреждённые файлы отдельно для диагностики, не удаляя их.

Снимки охватывают всю установку, а не одну кампанию. Загрузка изображений пока не реализована; при её добавлении формат резервирования потребуется расширить. Проверка структуры не является полной проверкой всех игровых значений. Графическое управление копиями и уведомления об ошибках в интерфейсе остаются следующей доработкой.
